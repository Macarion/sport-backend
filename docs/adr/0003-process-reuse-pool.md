# 进程复用池：驻留窗口 + web 内字典 + 显式 start 协议

同项目连续测多名学生时，每会话新建用户进程导致约 8 秒模型加载等待。决定：`BaseSport` 采用四段生命周期（load/reset/process/close），会话结束不再销毁进程，而是进入 60 秒驻留窗口等待同项目下一个会话复用；空闲池为 web 进程内字典，不引入独立 Manager 进程；会话边界用显式 `{'type':'start'}` 控制消息定界，worker 完成 `reset()` 后回发 `ready`（`ready` 的事实源保持在 worker，复用与冷启动对前端无差别）。

## Considered Options

- **Manager 服务器进程**：被拒。单 daphne 实例下没有第二个消费者，队列本就在 web 进程直建直传，Manager 只增加一种故障模式。
- **隐式定界（`finished` 后的第一个任务即新会话）**：被拒。依赖"旧会话帧已全部排空"的隐含假设，无法在协议层证伪。
- **常驻保温（每运动类型至少留 1 个）**：被拒。场景为阵发性，60 秒驻留窗口已覆盖连续测试间隔；并发产生的多个空闲进程各自独立计时，无需类型级封顶或常驻。
- **结果经 web 中转回 worker**：被拒，见 ADR-0004。

## Consequences

- web 重启即清空池（worker 为 daemon，随 web 退出），属预期。
- 会话收口（stop/断线/会话空闲）从"销毁进程"改为"归池"，只回收 shm 槽与会话条目；同时须修复 `_pump` finally 按 uid 无条件 pop 的竞态（改按会话对象身份）。
- `error`/异常的进程直接退出，不入池。
