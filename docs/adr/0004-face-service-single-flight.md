# 人脸识别独立服务与单任务无排队

人脸门禁须在计数开始前完成，而识别模型（ArcFace ONNX 166MB）首次加载为秒级、单次推理可达数百毫秒，帧循环不可阻塞。决定：人脸服务为独立进程，web 启动时即异步预载模型；识别请求携带 `reply_to` 队列直回所属用户进程的 `in_q`，由 worker 转交 `BaseSport.handle_control(msg)`（新增 ABC 方法）；识别采用**单任务无排队**——任务在途时新到达的帧不获得识别资格，任务完成后由下一帧重新触发。流程上，环境检测通过后进入人脸门禁阶段（`phase:'face'`），每次结果以 `phase:'face_result' {ok, conf}` 回传前端，通过后才发出 `ready` 进入读秒。

## Considered Options

- **worker 内联同步调用**：被拒。预载完成前的首次调用会秒级卡死帧循环；异步服务把等待移出热路径。
- **识别请求排队（每帧入队）**：被拒。识别耗时波动时队列积压使延迟复合增长；实时视频场景宁可少识别几帧，也不让门禁越等越久。
- **结果经 web 中转**：被拒。web 落在识别热路径上，多一跳且多一个故障点；mp.Queue 多生产者允许 worker 直写自身 `in_q`。
- **未注册学生拦截**：暂缓。人脸库尚为空，先以"放行 + 提示"过渡（18.b），录入铺开后收紧为拦截。

## Consequences

- 识别结果天然可能跨越多帧，评测状态机必须按"结果属于哪次触发"消费，而非按帧对齐。
- 识别阶段的画面评测照常进行，仅计数被门禁挂起。
- 前端提示完全由 `phase` 消息驱动。
